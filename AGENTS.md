# Правила разработки

- Небольшие функции и модули; минимум необходимого кода без потери ясности.
- Ветки `codex/<задача>`, небольшие коммиты, PR в `main`. Не пушить в `main`.
- Прикладная логика не зависит от Hermes, Telegram и транспорта ComfyUI.
- Hermes подключается тонким адаптером; его OAuth и агентный цикл не дублируем.
- Модель диалога OpenRouter настраиваем штатным провайдером Hermes, отдельно от
  генераторов. Ключ — только в .env профиля; пустая настройка сохраняет провайдера,
  явная модель без ключа вызывает ошибку до записи конфигурации.
- Каждая модель генерации — отдельный tool с фиксированной моделью. Общие HTTP,
  валидация и хранение переиспользуются; будущий MCP оборачивает те же функции.
- В действующем профиле генерация — MCP drawer_generation (stdio) только Nova.
  Text, Style и Depth — отдельные tools, без Character/InContext, All In One/Pose.
  Character удалён из схем, batch, workflow и рабочих skills; история сохранена.
  Старые native drawer_anima/batch/sheet отключены при generation_mcp=true.
  Z-Image, Flux, Alibaba
  и штатный ChatGPT image_gen отключены в схемах, регистрации и toolsets.
  Старые workflow и задания сохраняем для истории, но агент их не запускает.
- Пользовательские данные, секреты, OAuth, БД, изображения и веса не коммитим.
- Конфигурацию документируем в `.env.example`; реальные значения — в `.env`.
- Логи и сообщения об ошибках не содержат токены и содержимое `.env`.
- Внешние зависимости и версии инструментов закрепляем в `uv.lock`.
- Локально используем Python, установленный Hermes; отдельный Python не ставим.

## Типизация и документация

- Все функции и методы полностью аннотированы, включая `-> None`.
- Каждая функция имеет содержательный Google docstring: публичная, приватная,
  вложенная, async, конструктор, property, тест и fixture. Классы и модули тоже.
- `Args`: все входные аргументы, смысл, ограничения, единицы и defaults, где есть.
- `Returns`: тип и смысл результата, включая `None`; `Yields` — для генераторов.
- `Raises`: все исключения, выходящие из функции, и условия их возникновения,
  включая исключения вызываемых функций. Не выдумывать несуществующие ошибки.
- `Attributes` в docstring класса: все поля класса и экземпляра, включая приватные,
  с типами и назначением. Поля явно аннотируем на уровне класса.
- Документируем побочные эффекты. Описание должно объяснять смысл, а не имя.
- Аннотации и docstrings согласованы. Не используем `Any`, `cast`, `type: ignore`
  и `noqa` без локального объяснения необходимости.
- Типы в аннотациях callbacks Hermes импортируем во время исполнения: Python 3.14
  вычисляет их при `inspect.signature`. Проверяем зарегистрированный partial и
  настоящий hook dispatcher; прямой вызов функции не заменяет такую проверку.
- Полноту транзитивных исключений проверяем при ревью: линтер её не доказывает.
- Не отключаем проверку документации в тестах и приватных функциях.

## Проверки

- Перед коммитом: `uv run poe check`; перед PR также `uv run poe audit`.
- Ruff: все совместимые правила, Google convention, единый formatter.
- Mypy strict + Pyright strict, Pylint, pydoclint, interrogate (100%), Vulture,
  deptry, Bandit; аудит зависимостей через pip-audit.
- Pre-commit и GitHub Actions запускают те же команды; CI на Windows и Linux.
- Любое подавление проверки должно иметь точный код и причину.
- Для поведения пишем pytest-тесты: сроки, часовые пояса, перезапуск, ошибки API,
  отмена и повтор заданий. Сетевые сервисы в обычных тестах заменяем фикстурами.
- Живые тесты Telegram, OAuth и GPU запускаем отдельно и явно.
- Не утверждаем, что бот или GPU-интеграция работают, пока не проверили их.
- Gateway запускаем один на хосте, явно из `--profile default`, без `.env` проекта.
  Токен и правила Telegram записывает `uv run drawer-setup` в профиль помощницы.
- Доступ задаётся DRAWER_TELEGRAM_MODE=group/private и одним числовым chat id.
  Текущий рабочий режим — private: только личка художницы, другие DMs и группы
  запрещены. Для private user grant совпадает с положительным chat id; group
  сохраняет отрицательный id и закрытые DMs. Username не используем как grant.
- В разрешённой группе/теме общая сессия участников, включая историю и /model.
  Для multiplex Hermes флаги group_sessions_per_user/thread_sessions_per_user=false
  нужны также в конфиге хоста; его исходник сохраняем. Это глобальный режим хоста.
  Проверяем ключи сессий для двух участников, соседней группы и соседней темы.
  Старые истории не удаляем и не склеиваем автоматически. Приём реплик без
  обращения к боту и доступ из других групп при этом не включаем.
- В Telegram-альбоме упоминание общее: собираем кадры до проверки обращения,
  скачиваем все принятые файлы до вызова агента; группа/тема/отправитель изолированы.
  Совместимость Hermes — версионированный патч с проверкой применимости, без
  ослабления mention/access правил. При обновлении повторяем тесты адаптера.
- `DOC502`/`DOC503` можно подавлять локально с объяснением только для исключений
  вызываемых функций: pydoclint видит лишь явные `raise`, но документация их нужна.

## Данные и генерация

- Источник истины — выбранная БД: SQLite по умолчанию или PostgreSQL через
  DRAWER_DATABASE_URL в .env конкретного профиля. URL не пишем в settings.json,
  ошибки или repr; кеши изображений остаются локальными. Схемы версионируем.
- Переносим через согласованный snapshot и одну транзакцию в пустую PostgreSQL;
  проверяем все строки и бинарники хешами. Отличающуюся базу не перезаписываем.
  До переключения останавливаем записи; сохраняем исходник и план отката.
- Изображения референсов храним BLOB/ BYTEA вместе с SHA-256 и MIME; url/кеш
  Telegram не заменяют байты. Метаданные и привязку пишем одной транзакцией,
  одинаковые байты дедуплицируем. В tool-ответе только метаданные; get восстанавливает
  отдельный файл для MEDIA/генератора. Старые ссылки не объявляем сохранёнными фото.
- Заказы: название, клиентка, ТЗ, комментарии, дедлайн, приоритет 1/2/3.
  Этапы вложены через parent_id в один заказ; завершение хранит описание,
  комментарии, время и связи с бинарными референсами, не отдельные заказы.
  Проверяем циклы, чужие родители и принадлежность изображений заказу.
- Время сохраняем однозначно в UTC, рабочий часовой пояс — Europe/Moscow.
  Пользовательские часы — 12-часовые AM/PM, МСК; API принимает ISO с offset.
  Миграции меняют отображение, сохраняя момент дедлайна и состояние доставки.
- Напоминания отправляет worker без LLM; отправки и повторы учитываем в БД.
  Штатный cron Hermes проверяет их раз в 30 минут. Отдельный агентный cron
  в 12:00 PM МСК читает семь дней и просрочки, предлагает приоритеты без записи.
  Для него только drawer_read: карточка и сводка. Установка обновляет cron по
  имени, не создаёт дубли. Выбранная БД остаётся источником истины; todo Hermes
  не используем как постоянную базу. Оформление карточки — отдельный tool;
  процедуры заказов и сводок — skills, личность — SOUL.
- Сообщения для художницы: короткие блоки с пустыми строками, главное сначала,
  смысловые заголовки, минимум emoji и украшений. Общая процедура —
  drawer-readable-messages, краткие правила — .hermes.md. Формат карточки и
  напоминания задаёт код; данные тулов остаются структурированными. Не выдавать
  JSON/traceback в обычный ответ. Полные данные не удалять ради краткости.
  HTML напоминаний экранирует все пользовательские поля до отправки.
- Штатный cron: wrap_response=false, mirror_delivery=true, Telegram surface
  in_channel. Сводка без служебных header/footer попадает в общий контекст группы.
  При изменении priority отправляем только id/action/priority; не трогаем сроки,
  timezone и notes. Europe/Moscow выбран явно, не «чинить» его по старым заметкам.
- ComfyUI доступен по HTTP(S); локальные Windows-пути серверу не передаём.
- Workflow в формате API и версии моделей/nodes фиксируем; веса храним отдельно.
- MCP Anima добавляет согласованный quality/painting/scenery prefix один раз.
  Positive prefix и negative — defaults с явной заменой через options, включая
  пустую строку. Конфликт со стилем агент разрешает до вызова, сохраняя замысел.
  Все refs сначала ImageScale stretch до размера генерации без crop/padding.
  Defaults: 512x512, CFG7, 45 steps, res_multistep/simple, denoise1.
  Инструкция Hermes — `src/drawer_assistant/skills/drawer-anima/SKILL.md`;
  endpoint Anima можно задать
  отдельно через `COMFYUI_ANIMA_BASE_URL`, с fallback на общий адрес.
- Генерация — общий инструмент, не привязанный к заказам. Правила промптинга
  находятся в drawer-anima; мультипанели генерируем отдельными заданиями и собираем
  drawer_image_sheet через локальный ImageMagick 7. Исходники сохраняем, порядок
  фиксирован входным списком, подписи рисует редактор. Без shell и произвольных
  аргументов CLI; границы размеров/количества и timeout проверяем в коде.
- Действующий сервер Anima — ПК художницы через Tailscale Serve. Отдельный URL
  Anima оставляем пустым, чтобы не перекрыть общий адрес устаревшим облачным.
  Проверяем реальный system_stats, GPU-only и наличие весов до живого теста.
- Мок проверяет протокол и ошибки, но не качество, скорость или VRAM.
- Исторические Anima controls — experiments/anima-controls. MCP workflow —
  generation/workflows; успешный запуск каждого режима на целевом GPU отмечаем
  отдельно. Missing dependencies никогда не выдаём за успешную генерацию.
  Depth возвращает именно карту входа ControlNet + start/end окно. Окно задаёт
  этапы denoising, не фильтрует карту. Не рисуем вымышленный изменённый preview.
  Batch хранит defaults и независимые options/refs каждого кадра, исполняется
  последовательно, переживает перезапуск и не повторяет неопределённый POST.
  Флаг GPU-only не запрещает сторонним нодам собственный offload. SigLIP оставляем
  со штатной выгрузкой на CPU; не патчим удержание в VRAM. Depth не содержит
  специальной обработки reference frames старого AiO. Версии и патчи фиксируем явно.
- Anima status ждёт результат до 25 секунд с паузой 5 секунд между проверками;
  БД не держим открытой во время паузы. Агент делает не более трёх status на кадр
  за ответ, затем честно сообщает pending. Не отключаем loop guardrails.
- Мультипанельный drawer_anima_batch хранит неизменный spec в image_batches
  (миграция 6), запускает отдельные idempotent jobs на каждый prompt и собирает
  только полный результат. status сохраняет порядок, прогресс и времена кадров.
  Не повторяем неопределённый POST. Одиночный drawer_anima явно перенаправляет
  промпты с числом панелей/сеткой к batch; старые задания остаются доступны.
- Alibaba: ключ читается из .env конкретного профиля, не общего gateway; не передаём
  его CDN при скачивании. До POST сохраняем intent, неизвестную отправку не повторяем.
  Positive/negative раздельны; автодополнение выключено по умолчанию. Референсы
  отправляем провайдеру только как вход явно заказанной генерации/правки.
- Целевая карта — RTX 3080 10 ГБ, бюджет — до 9 ГБ VRAM. CPU/RAM offload
  запрещён для diffusion, текстового encoder и VAE; штатная выгрузка SigLIP
  разрешена пользователем. Испытания L40 не выдаём
  за результат на 3080. Указываем единицы и метод замера.
- Основной продукт — Джессика, заказы, дедлайны и референсы. Подбор моделей служит
  инструментам бота и не подменяет работу над основными сценариями.
- Персона: Джессика, дерзкая напарница, разговорно, мат уместен по ситуации.
  Шаблон персоны — `src/drawer_assistant/SOUL.md`; не дублируем её в коде.
  SOUL содержит только личность и стиль общения. Общие рабочие правила —
  `src/drawer_assistant/.hermes.md`; процедуры — `skills/drawer-*/SKILL.md`.
  Краткий контракт вызова и ссылка на skill — в tools.json; гарантии — в коде.
  Навыки плагина подключаем через skills.external_dirs, не перезаписывая навыки
  пользователя. Проверяем их обнаружение и skill_view в установленном Hermes.
  Действующая персона — SOUL.md профиля; обновление сохраняет пользовательские
  правки. Файловые и skill tools Hermes работают с профилем как текущей папкой;
  это рабочий каталог, а не файловая песочница ОС. Настройки защит Hermes сохраняем.

- Автодоставка генераций: native pre_tool_call сохраняет только доверенный origin
  разрешённого Telegram-чата в generation_deliveries до GPU POST. Worker без LLM
  продолжает singles/batch, штатная cron.delivery_queue доставляет и зеркалит итог.
  Не создаём второй poller/LLM cron. Локальные и исторические задания без маршрута
  не рассылать. Проверяем lease/restart, backoff, неопределённую отправку и dedup.
  При delivery.automatic=true агент не отправляет MEDIA повторно и не требует
  команду «проверь». Не обещаем exactly-once для сетевого API Telegram.
