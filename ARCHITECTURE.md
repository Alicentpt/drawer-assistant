# Архитектура и этапы

```text
Telegram → Hermes / Джессика
           ├─ drawer_orders → SQLite ← worker без LLM → Telegram
           ├─ drawer_references → SQLite
           ├─ drawer_zimage / drawer_flux_klein → ComfyUI HTTP → GPU-сервер
           ├─ drawer_qwen_image_3 / _3_pro / _2_1_pro → Alibaba DashScope API
           └─ image_generate (Hermes) → openai-codex OAuth → облачные картинки
```

Наш Python-плагин содержит заказы, референсы и задания ComfyUI/Alibaba. Облачный
`image_generate` предоставляет сам Hermes: toolset `image_gen`, настройка
`image_gen.provider: openai-codex`. OAuth и реализация облачного API остаются у Hermes.
Выбор инструмента делает агент по запросу и правилам персоны; общего Python-роутера
провайдеров нет. Каждая модель имеет свой tool; транспорт и хранение общие.
Z-Image и Flux — два фиксированных workflow внутри ComfyUI. Qwen-инструменты
вызывают async DashScope: start → task_id → status → PNG + MEDIA.
SQLite сохраняет intent до POST, параметры и fingerprint запроса, модель,
endpoint, task_id, результат и серверное время; неизвестный POST не повторяем.
Локальные референсы кодируются в Base64; ключ читается из .env именно этого
профиля, не из окружения общего gateway. MCP позже обернёт те же функции.
Маленький Python-пакет позволяет добавить MCP позже, если он понадобится.
Hermes переиспользуем для диалога, Telegram и OAuth. ComfyUI-картинки храним файлами,
их метаданные — в SQLite; Alibaba сохраняем так же, ChatGPT обрабатывает Hermes.
Схема v4: `refs` содержит заметки/источник/order_id, `reference_files` связывает
референс с SHA-256 и именем, `assets` хранит MIME и BLOB. Один бинарник используется
несколькими референсами. Запись метаданных и файла атомарна; при замене удаляется
только бинарник без оставшихся ссылок. Hermes передаёт путь кешированного вложения,
save копирует байты в БД; get проверяет SHA-256 и восстанавливает MEDIA-файл.
Пути экспорта и кеш Telegram не источник истины. API/list не возвращают байты LLM.
Миграции v1–v3 сохраняют заказы, задания и старые ссылки без выдуманных вложений.
Данные лежат
вне репозитория, в `DRAWER_DATA_DIR`
и профиле Hermes `drawer-assistant`; версия кода обновляется отдельно от данных.

## 0. Окружение

Windows, Python из Hermes, uv, правила, Google docstrings, статические проверки,
pre-commit, CI, `.env.example`. Вся разработка в ветках с PR.
Hermes на этом ноутбуке при подготовке: commit
`68420e1912a43949d4973df0ecf3c423b4370345`, Python 3.14.7.
Это запись установленной ревизии; перед интеграцией фиксируем проверенную версию.

## 1. Два инструмента

Реализовано для первого теста: персона Джессика, native plugin `drawer`, заказы,
перенос/закрытие сроков, ссылки и бинарные референсы, cron без LLM и очередь ComfyUI.
Инструменты зарегистрированы отдельно: orders, references, generate.
Генераторы теперь разделены по моделям; общий drawer_generate убран из меню.
Таймер вызывает `.venv` проекта; SQLite сериализует отправку и изменение заказа.
HTTP-запросы ограничены 30 секундами, статус GPU-задания хранится между вызовами.

- Дедлайны: создать, перенести, завершить, показать; часовой пояс, SQLite,
  напоминания без LLM, журнал отправок, повтор после сбоев.
- Референсы: текст/исходник → задание → картинки. Облако — штатный image tool
  Hermes; ComfyUI — HTTP-клиент к GPU-серверу. Для тестов без сервера — HTTP-мок.
- Первые живые проверки: ChatGPT OAuth, одна генерация и одна правка.
- Уже проверены: OAuth-диалог, вызов orders из Hermes, генерация PNG новым
  ComfyUI-клиентом на L40. Облачная картинка/правка и GPU на 3080 ещё не проверены.
- Alibaba: протокол, референсы, миграция и восстановление проверяются моками;
  живая генерация/правка требует DASHSCOPE_API_KEY выбранного региона.
- Приёмка: сохранность заказа после рестарта, отмена старого напоминания при
  переносе, получение картинки в Telegram, корректные таймауты/ошибки провайдера.
- Спящий ноутбук не отправляет напоминания; при запуске обрабатываем пропущенные.

## 2. База художницы и правки

Материалы и переписки при заказах, вариации и маски, продолжение заданий после
перезапуска. Проверенные GPU-workflow, версии custom nodes и манифест моделей.
GPU-сервер для испытаний предоставляет пользователь.

## 3. Тренды и передача

Выбранные площадки, примеры с источниками и датами, идеи адоптов/YCH.
Лайки, объявленная цена и подтверждённая продажа — разные признаки.
Далее: установка, обновления, миграции, резервные копии и постоянный worker.
