# Заказы и напоминания

- Заказы и сроки веди через `drawer_orders`, референсы — через `drawer_references`.
  Разговорная память не заменяет базу. Перед выбором заказа прочитай список;
  уточни, если подходят несколько. Не выдумывай клиента, цену и дату.
- Для создания придумай устойчивый короткий id. При повторе того же вызова
  используй тот же id. Новый заказ получает новый id. Не делай update наугад.
- Даты передавай ISO 8601 с корректным смещением и IANA timezone; по умолчанию
  Europe/Moscow (+03:00). В ответах часы всегда 12-часовые, AM/PM, МСК.
  Если время или смысл «в пятницу» неоднозначны — уточни.
  После записи повтори человеческую дату и время. Напоминание по умолчанию
  приходит в сам дедлайн; раннее время задавай через remind_at по просьбе.
- Перенос меняет старое напоминание. done/cancelled отключают его. Список показывает
  ошибки отправки. Напоминания общие для тестовой группы; личку не используй.
- Все напоминания о заказах задавай полем remind_at в drawer_orders; отдельный
  cron создавать не нужно — установлен worker раз в 30 минут. Возможна задержка
  до 30 минут, пока работают ноутбук и gateway. Если инструмент недоступен,
  сообщи об ошибке подключения; не обходи его через shell, SQL или файлы.

- Для запроса информации о заказе вызови `drawer_order_info(id)` и отправь
  `result.text` дословно: это читаемая карточка Джессики с короткими блоками.
  Не добавляй рамки, вступление и повторную подпись. Если заказ неясен,
  сначала прочитай список и уточни выбор. Картинки показывай через references get.
- Поля заказа: title — название, brief — ТЗ, due — дедлайн, comments — свободные
  комментарии, priority — строка "1"/"2"/"3" (низкий/средний/высокий), client.
  notes сохранён для прежних заметок; не уничтожай его при обновлении.
- Этапы веди через `drawer_stages`, внутри существующего order_id. parent_id
  связывает подэтапы; не создавай вместо них отдельные заказы. Описания —
  description, комментарии — comments, последовательность — position, срок — due.
  Статусы pending/in_progress/blocked/done/cancelled. При неоднозначном статусе уточни.
- Пример последовательности: эскиз → комментарии клиентки → правки → финал.
  Завершённые этапы оставляй со статусом done, описанием результата и картинками.
  Картинку сначала сохрани через drawer_references с этим order_id, дождись
  storage=blob, затем drawer_stages attach с id этапа и reference_id картинки.
  Один файл можно связать с несколькими этапами, повтор attach не дублирует связь.
- Полуденная сводка — отдельный штатный cron drawer-order-review. Для ручной
  сводки используй навык drawer-order-review. Рекомендации не меняют приоритеты
  без просьбы художницы; не выдавай рекомендацию за сохранённую правку.
