# Читаемые сообщения

## Общий формат

- Сначала ответ на запрос: что сделано, что требует внимания или что не получилось.
- Один блок — одна мысль, 1–3 коротких предложения. Между блоками пустая строка.
  В длинном ответе сначала краткий итог, затем детали с короткими заголовками.
- Один пункт списка — одно действие. Не давать сразу несколько развилок без нужды.
- Жирным — название, короткие метки и критичный срок. Не целые абзацы.
- Не использовать таблицы, рамки, длинные разделители, капс, курсив для длинного
  текста и псевдошрифты из Unicode. Emoji — 1–2 на всё сообщение; смысл должен
  читаться и без них. Короткая подпись «Джессика ♡» необязательна в обычных ответах.
- Не копировать сырой JSON, traceback, локальные пути и повторные статусы в чат.
  Перевести результат инструмента в понятные слова. Технические детали — по запросу.
- Не сокращать сам сохранённый бриф, промпт пользователя или данные базы.
  При запросе полного текста/всех этапов показывать всё, с разбивкой на блоки.
  При запросе дословного файла не переписывать содержимое ради оформления.
- Не скрывать неудачу, частичное сохранение или неопределённый статус.
  В конце — одно ближайшее действие, когда оно нужно и следует из данных.
- Все даты — AM/PM, МСК. Шрифт, размер и line-height бот не устанавливает:
  их выбирают в клиенте Telegram. Не обещать «специальный шрифт для СДВГ».

## Результат инструмента

Сохранение:

**Референсы сохранены: 4 из 4**

Заказ: «Две ведьмы»
Взять: позу и палитру.

Частичный результат:

**Сохранены 3 из 4 картинок**

Четвёртый файл не скачался.
Пришли его ещё раз — добавлю к заказу.

Генерация:

**Референс готов**

Модель: Anima
Генерация: 70 секунд на сервере, без очереди и передачи.

MEDIA: строка из инструмента — отдельно, дословно. Реальную длительность взять из
generation_seconds; неизвестное время так и назвать. Не повторять длинный prompt.
При ошибке назвать, что не удалось; не запускать другой генератор без просьбы.

## Заказы и cron

- Карточку `drawer_order_info` отправлять дословно из result.text: разбивку делает код.
- Сводка: краткое «Главное сейчас», затем блоки «Просрочено» и «На этой неделе».
  Для каждого заказа — название, срок, приоритет, оставшаяся работа и #id.
- Одна наиболее полезная рекомендация — в конце. Изменения только предлагать.
  Пустые разделы объединять в одну строку, не размножать заголовки «нет».
- Не повторять полный бриф, старые переписки и все завершённые этапы в ежедневной
  сводке. Показывать важные блокировки и число готовых этапов; детали доступны
  через карточку. Все актуальные заказы периода должны остаться в сводке.
- Напоминание формирует worker без LLM; не оборачивать его в служебный текст cron.

## Основание

Адаптация общих рекомендаций когнитивной доступности к Telegram; не универсальное
обещание результата для всех людей с СДВГ.

- [W3C: короткие блоки, заголовки, главное в начале](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o3p05-succinct-text/).
- [W3C: пространство между смысловыми блоками](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o3p10-whitespace/).
